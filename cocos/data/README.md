# 卡牌数据源

修改 `startx_data.xlsx` 后，在 `cocos/` 目录执行 `npm run build:web` 或 `npm run build:wechat`。构建会先校验表格，再生成游戏数据、卡面、数字贴片和配方图标。Excel 内容没有变化时复用已有文件。

| 工作表 | 内容 |
| --- | --- |
| `cards` | 卡牌名称、类型、工资、产能、价值、成本、次数、生产时间和说明 |
| `recipes` | 配方输入、消耗数量、产出数量、员工条件、卡包归属 |
| `packs` | 卡包名称、价格、阶段、抽取数量和各候选卡牌的权重 |
| `tasks` | 任务名称、说明、目标、分组、排序和解锁卡包 |
| `stages` | 各阶段的最低月份、营业收入及必需任务，按行依次解锁 |
| `events` | 客户事件、关联卡牌、触发时机、时限、延期秒数和尾款金额 |

`id` 用来关联卡牌、配方、卡包和存档，修改名称时保留原来的 `id`。`recipes` 每行会自动生成一张 `bm_<配方 id>` 商业模式卡。`maxUses` 支持固定值和 `3-5` 这样的范围；留空表示无限次。表内计算公式使用 Excel 保存的计算结果，修改后先让 Excel 完成计算再保存。

成交金额直接取 `recipes` 中现金的产出数量；产能只影响制作速度。`effect` 指定订单交付或客户事件的处理方式，`workRequired` 可覆盖配方的工作量。新内容名称以“（临）”结尾。

订单的 `deadlineSeconds`、`firstDeadlineSeconds`、`expiryPenalty` 分别控制普通单时限、首单时限和逾期扣款。点击接单或叠入产品后才计时，同时只接一单；首单逾期免罚。尾款到账前不计入现金。商战 HP 等于散装现金加账户余额，受击时即时扣款，先散装后账户。

`packs.requiredTasks` 填必需任务 id，`starterCards` 填该卡包首次购买时的保底卡；多个 id 用逗号分隔，重复 id 表示多张。卡包同时满足阶段和任务条件才开放。产品升级包需完成账户任务并进入第 2 月；完成 3 张订单且进入第 3 月后开放市场竞争阶段。

新增卡牌时，把透明插画放到 `art/cards/<卡牌 id>.png`，也支持 `.svg`；PNG 优先。新增卡包的插画放到 `art/packs/<卡包 id>.png`。商业模式卡共用 `art/cards/business_model.png`。生成的卡面在 `../assets/content/faces/`，卡包封面在 `../assets/content/packs/`，这两处会由构建更新。

`balance.json` 保存月末结算等全局数值，`idea_pools.json` 保存商业模式想法池。研发系统及研发点已移除。字体、猫咪启动图和卡包纹理也保存在本目录，构建不依赖项目外的素材或字体安装。

左下角供应链按钮依次执行“选择主体、自动识别另一组牌堆的上下游、虚线预览、完成连接”。上下游按配方的产出与需求匹配，支持同一牌堆同时接入上游和下游；连接不再消耗研发点或连接额度。相同连接不会重复创建。旧存档继续恢复经营进度，旧研发字段不再使用。

Creator 编辑器内的普通构建通过项目扩展 `startx-data` 执行同样的同步。表格引用不存在的卡牌、重复 id、无效数量或缺少插画时，构建会给出具体位置并停止，保留上一份完整资源。

卡牌配色在 `../tools/render-cards.cjs` 统一定义：人物珊瑚粉、对手砖红、商业模式薰衣草紫、生产／供给点灰蓝、办公／教育设施蓝灰、客户奶油黄、财务卡金黄、产品暖橙、其余工具／课程／文书合同棕褐、订单草绿、客户事件粉紫。`resource` 包括小区、市场、律所和银行，`facility` 包括大学、办公桌和工位；账户虽归在 `tool` 中，配色与现金、应收尾款一致。标题和圆圈使用同一个强调色。现金与账户的暖金浮光随画面变化，数字贴片同步使用同一组参数。
